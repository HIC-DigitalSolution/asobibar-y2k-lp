# 料金を体験より前に出して、順番が壊れた

- **Hit:** 2026-09-04

## Symptom

依頼者の言葉:「**上から出す順番が結構壊滅的だね。元作ってたやつの方が
並び方が綺麗でわかりやすかった。**」

構成の組み直し（[lp-restructure-plan-a](../exec-plans/active/lp-restructure-plan-a.md)）で、
`#price`（料金）と `#event`（開催情報）を体験3本より**前**へ移していた。

| | 並び |
| --- | --- |
| 元 | 表紙 → 曲リクエスト → カラオケ → チェキ → MIX → 料金 → 開催情報 → HOW TO → 予約 |
| 組み直し後 | 表紙 → **料金 → 開催情報** → 曲リクエスト → カラオケ → チェキ → MIX → HOW TO → 予約 |

**機械の検証は全部通っていた。**ノンブルも連番、CTAの死角も0、コントラストもAA。
壊れていたのは**話の順番**で、これを見る仕組みは harness に無い。

## Root cause

**同じ問題を2回解いて、2回目が順番を壊した。**

exec-plan の Goal は「いつ・いくら・何がもらえるかが**3画面以内**で揃う」だった。
これに対して**2つの手を打っていた**:

1. FVの中に `期間 / 料金 / 特典` の事実3つを置いた（`.cover__facts`）
2. **料金セクションそのものを前に出した**

**1で「いくら」には既に1画面目で答えている。**（実測: PC 1440×900・SP 390×844 とも
FV内に3つとも表示され、CTAも画面内）。2は同じ問いにもう一度答えているだけで、
**得たものは無く、代わりに話の順番を失った。**

これは `lp-cvr-knowledge` が名指しで禁じている形だった:

> **ストーリー性のある構成展開**: ターゲットの悩みに寄り添い、感情の変化に沿って
> 説得力のある順序で展開する。（§4）

> 構成順序が「**悩み → 共感 → ベネフィット → 証拠 → CTA**」の流れになっているか
> （「この知識をどう効かせるか / 作りながら確かめるもの」）

体験3本（曲リクエスト・カラオケ・チェキ）と MIX が**ベネフィット**、
料金・開催情報・HOW TO が**証拠と条件**。**料金を前に出すのは、
欲しいと思う前に値札を見せること**で、順序を1つ飛ばしている。

**読んだのに効かなかった。** 着手前に `lp-cvr-knowledge` は読んでいた。
「3画面以内」という自分で立てた数値目標が、文書に書いてある順序より
手前で判断を止めていた。**数値目標は順序の制約より弱い**（数値は別の手段でも満たせるが、
順序を崩すと戻すのに全セクションの移動が要る）。

## Fix

`index.html` の `.info-zone`（`#price` ＋ `#event`）を `#mix` の直後へ戻した。
`.experience-zone` の中で `request → karaoke → cheki → mix → info-zone` の順。
**元の並びと同じ**（元にあった `#song-pet` の寄り道だけは戻していない）。

- `data-page` を `01..08` に振り直し（`#top` は `#experience` と 01 を共有）
- `.scene-label` の見える番号、フッターナビの並びも合わせた
- FVの事実3つ（`.cover__facts`）は**この時点では残した**が、
  **同日さらに依頼者の判断で削除した。**順番はそのまま（下記）

検証（ヘッドレスChrome、SP 390×844 / PC 1440×900）: ノンブル 01〜08 を
100px刻みで全域走査して**不一致0**、固定CTAバーの死角**0**、横スクロールなし、
JSエラー0、`[data-reveal]` の隠れ残り0。

## その後（同日）

**FVの事実3つも依頼者の判断で削除された。**FVはキービジュアルとCTAだけになった。

**この gotcha の「2回解いていた」という診断は変わらないが、
いまは0回になっている。**「いくら」に1画面目で答える手段はページ上に無い。
**それでも料金セクションを前に戻すのは違う** ——
順序（ベネフィット → 条件）は依頼者が明示的に選んだもので、
「いくら」を早く出したいなら**FVの中で解く**（＝一度やって消したもの）か、
**出さないと決める**かのどちらか。**順序で解こうとしない。**

## Avoid next time

- **順番を動かす前に、`lp-cvr-knowledge` の「悩み → 共感 → ベネフィット → 証拠 → CTA」に
  現状と変更後の両方をマッピングして exec-plan に書く。**
  読んだだけでは効かない。**書き出すと、飛ばしたことが目に見える。**
- **同じ問いに2つの手を当てていないか数える。** 1つで満たせているなら、
  2つ目は「効かない変更」ではなく**別の何かを壊す変更**になる
  （`lp-visual-knowledge` §7「変更を1点に絞る」と同じ話が、構成側にも効く）。
- **自分で立てた数値目標（総丈・画面数）は、文書に書いてある順序より弱い。**
  数値は別の手段でも満たせる。順序は崩すと全セクションの移動になる。
- **機械の検証が全部通っても、順番が良いことの証明にはならない。**
  harness にあるのはノンブルの連番・死角・コントラストで、
  **話の順序を見る仕組みは無い**。ここは人が見る。
