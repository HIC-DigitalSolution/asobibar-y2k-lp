# 店舗選択ダイアログを2ステップに組み直す

- **Started:** 2026-09-07
- **Rule:** [docs/design-docs/lp-visual-knowledge.md](../../design-docs/lp-visual-knowledge.md)
  §1 世界観は「1つの決定」で作る / §2 彩度はCTAのために取っておく /
  §4 読ませたい場所に世界観を持ち込まない / §5 アクセントは2色だけ
- **Completed path:** `docs/exec-plans/completed/storepick-two-step.md`

## Goal

予約CTAから開くダイアログを、**装飾の数と画面設計の両方**から直す。
「押したあと急にちゃっちくなった」と言われた状態を、
**彩度を持つのがLINEの緑1色だけの白いシート**に置き換え、
9店を1画面に並べるのをやめて**エリア→店舗の2ステップ**にする。

## なぜ

依頼者（社長）の指摘を受けてカンプを3案出し、案C（エリア→店舗）が選ばれた。
カンプ: https://claude.ai/code/artifact/009df893-c5bc-4d73-b566-21f2ad8c0657

実測で分かった中身は2つある。

1. **緑のボタンがLINEの緑ですらなかった。** `linear-gradient(170deg, #e7ffd0, #a7d472 54%, #7cae4c)`
   にベベルと内側ハイライトを掛けたもので、2005年ごろのWeb2.0のジェルボタン。
   LINEの正規ブランドグリーンは `#06C755`。
2. **1枚に彩度の高い色が4つ**（マゼンタのタブ・シアンの枠・液晶の若草色・黄緑のボタン）。
   本体のCTA（ローズ `#f14c93`）より強い色が予約導線に出ていた。§2 に反する。

さらに構成の問題が実測で1つ出た。

3. **2タブ式では iPhone SE (375×667) に6店中3店しか入らず**、
   リストは `overflow-y: auto` で実際にスクロールするのに、
   **スクロールできると分かる手掛かりが何も無かった。**

## Scope

- [x] 装飾を落とす：ちぎれ紙・マステ2枚・液晶帯・網点のタブ・シアンの枠・点線の罫線
- [x] ボタンを `#06C755` のベタに（グラデ・ベベル・内側ハイライトを全部外す）
- [x] 2タブ（関西/東京）→ **5エリアのチップ**（神戸・大阪・名古屋・福岡・東京）
- [x] エリアごとの店舗パネル。既定は先頭（神戸）
- [x] 開く動きを「ガラケーが開く」回転から、下から上がるだけに差し替え
- [x] ダイアログ内のフォーカスリングをシアンから墨へ
- [x] 小さい文字のコントラストを実測して直す
- [x] 使わなくなったCSSを削除（`storepick__lcd` `__ant` `__tabs` `__tape1/2` `__empty` `__face`、
      `storepickFlip` `storepickLcdOn` `storepickBar` `storepickTape`）

## Non-scope

- 店舗の住所は出さない。**カンプの案Cには住所を入れたが、あれは飾り。**
  落とせば店舗確認を待たずに実装できるので落とした。
- 料金は店舗ごとに出さない（LPが定義しているのは関西/関東の2区分だけ。名古屋・福岡の額は未確認）。
- `.sheet` `.sheet--torn-bottom` `.sheet__fiber` は他の節が使っているので触らない。

## Constraints

- **店舗ごとのLINE URLは変えない。** 既存の `data-line` をそのまま移設する。
- `<dialog>` を使い続ける（Esc・フォーカスの閉じ込め・背面の inert 化）。
- 店舗リンクは同一タブで開く（アプリ内ブラウザが `_blank` を落とすため）。
- JSの仕組み（`data-storepick-tab` / `data-storepick-panel` / `syncMore`）は変えない。
  変えたのはタブが2つから5つになったことだけ。

**組み直し前は SP 375×667 で6店中3店だった。**

`max-height` は `88svh` → `92svh` に上げている。**東京(3店)が 375×667 に
収まる下限がそこ**だった（88svhでは3店目が19px切れる）。

長い店舗名（新宿歌舞伎町タワー前店）は、`max-width:400px` の `flex-wrap` で
ボタンが下に落ち、そのカードだけ縦に伸びていた。`flex:1 1 auto; min-width:0` と
ボタンの左右padding を `clamp(13px, 3.4vw, 16px)` にして、**3枚とも76pxで揃えた**
（パネルの scrollHeight 254 → 220）。

### 未解決：LINEボタンの白文字は 2.26 で不合格

`#06C755` に白文字は**LINE公式のボタンの仕様そのまま**で、これがユーザーの見慣れた形。
AAの4.5に上げるには
(a) 緑を `#046b2f` 相当まで暗くする、または (b) 文字を墨にする（7.67）
のどちらかで、**どちらもLINEのボタンに見えなくなる。**
「LINEの緑ですらない」が今回の出発点だったので、**ブランドの緑を優先して残した。**
判断は依頼者に返す。数値は隠さない。

## 追加：余白のスケール（2026-09-07・依頼者の指摘を受けて）

指摘は2つ。**「料金を見る」を消す**／**上下の余白が綺麗になっていない、もっとゆとりを持たせる。**

### 「綺麗じゃない」の実体は、値の大小ではなく2つの欠陥だった

1. **`.storepick__step + .storepick__step` が一度も当たっていなかった。**
   隣接セレクタなので、あいだに `<nav class="storepick__areas">` が入る今の構造では
   マッチしない。**実測すると手順2の上余白は 0px** で、エリアのチップに貼り付いていた。
   `.storepick__areas + .storepick__step` に直した。
2. **縦の余白の基準が `vw` だった。** 詰まって見えるのは横幅ではなく**画面の高さ**が
   足りないときで、`vw` はそこに反応しない（iPhone SE 375×667 と iPhone 15 390×844 は
   幅がほぼ同じで高さが177px違う）。基準を `svh` に変えた。

### スケール

`.storepick` に置いた5段。左右だけは横幅に連動させる（`--sp-x`）。

| | 通常 | `max-height:700px` | `max-height:600px` |
|---|---|---|---|
| `--sp-1` くっつける | `clamp(5px, 0.9svh, 8px)` | 同 | 同 |
| `--sp-2` 群の中 | `clamp(8px, 1.4svh, 12px)` | 同 | 8px |
| `--sp-3` 見出しと中身 | `clamp(11px, 1.9svh, 16px)` | 11px | 10px |
| `--sp-4` 群と群・シートの上下 | `clamp(16px, 2.9svh, 26px)` | 15px | 13px |
| `--sp-5` 手順1と手順2 | `clamp(20px, 3.6svh, 32px)` | 18px | 15px |

**収まらない端末に合わせて全端末の余白を削らない。**短い端末でだけ落とす。

実測されたリズム（PC 1440×900）：`26 / 8 / 12 / 27 / 26 / 16 / 32 / 16 / 12 / 26 / 26`。
罫線の上下が 27/26 で対称、シートの上端と下端が同じ 26。

### エリアのチップを flex-wrap から3列グリッドへ

5個を折り返させると **4+1 になって「東京」だけが2段目に取り残され、幅も揃わない。**
`grid-template-columns: repeat(3, 1fr)` にして 3+2 の等幅にした。
どの端末幅でも崩れ方が変わらない。当たり判定は 38px → 40px。

### 収まり方（再実測・全店舗が切れずに見えるか）

| | 神戸1 | 大阪2 | 名古屋2 | 福岡1 | 東京3 |
|---|---|---|---|---|---|
| PC 1440×900 | ✓ | ✓ | ✓ | ✓ | ✓ |
| SP 390×844 | ✓ | ✓ | ✓ | ✓ | ✓ |
| SP 375×667 | ✓ | ✓ | ✓ | ✓ | ✓ |
| SP 320×568 | ✓ | ✓ | ✓ | ✓ | **✗ 1枚切れ** |

`max-height` は `92svh` → `94svh`。余白を広げたぶん 92svh では **375×667 の東京が3px**、
**320×568 の大阪が6px** 足りず、そこを内側から削り返すとせっかく揃えたリズムが崩れる。
外を1回だけ動かした。`vh` ではなく `svh` なのでモバイルのツールバーが出ている状態が基準。

**320×568（iPhone SE 第1世代）の東京だけは、どう詰めても入らない**（71px足りない）。
リストがスクロールし、下端のフェード（`[data-more]::after`）が「まだ続く」と伝える。
これは組み直し前からの既知の1件で、**改善はした**（1/3 → 2/3表示）。

### 「料金を見る」

`<a href="#price">` を削除。`.storepick__lead a`（`white-space: nowrap` を掛けていた）も
使われなくなったので消した。**「料金はエリア・曜日によって異なります。」の文は残す** —
指摘はリンクについてで、この情報自体は予約前に要る。
