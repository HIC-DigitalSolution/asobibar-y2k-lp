→ 元の並び（体験4本 → 料金 → 開催情報 → HOW TO → 予約）へ戻した。
[gotchas/section-order-benefit-before-price.md](../../gotchas/section-order-benefit-before-price.md)

**0-b. そもそも tonight と FAQ は要らなかった。**（2026-09-04、実物を見た依頼者の判断）
ワイヤーフレームの段階では「要約」と「不安の解消」の2枠として妥当に見えた。
**実物にすると、要約は後段の言い換えでしかなく、FAQ は答えを持っている4問しか
置けていなかった。**紙の上では成立して、ページの上では成立しない種類の枠だった。
**構造の穴を「節を足す」で埋めようとしたのが間違いで、
埋まっていなかったのは店舗への確認だった。**

**1. `#tonight` を `.scene` で組んで見出しが読めなかった。**（節ごと削除済み）
`.scene` は `background: var(--night-violet)` の暗い地。そこに
`.paper-h`（`color: var(--print-ink)`）を載せた。**暗地に暗字。**
FAQ と同じ `.sheet`（紙）に載せ替えた。計測後のコントラストは
見出し 16.19 / 本文 15.23〜16.01 で、AA本文 4.5 に余裕がある。

**2. PCのファーストビューから CTA が消えた。これがいちばん危なかった。**
`.cover__info` は ≥900px でキービジュアルの上に `position: absolute; top: 74%`
で置かれている。事実3行を縦に積んだらパネルが約200px伸び、
**1440×900 で CTA の下端が 927px（画面は900px）**になった。
固定CTAバーは01に着くまで出ないので、**PCの1画面目に押せるCTAが0個。**
→ PCでは事実を横1列に畳み（200px → 37px）、さらに
`top: min(72%, calc(100svh - 200px))` でビューポート基準に逃がした。
1440×900 / 1920×1080 / 2560×1440 / 1280×720 / 1024×768 / 900×700 の6サイズで再測。

**3. プレビューで見ようとして、実バグを1つ掘り当てた。**
アプリ内のブラウザペインが真っ白になるのは既知だと思っていたが、
**環境の癖ではなくこのLPの作りだった。** `motion-ready` / `reveal-ready` を
付けた時点で本文が `opacity: 0` になり、IntersectionObserver のコールバックが
返らない環境では**中身が消えたまま残る。**`"IntersectionObserver" in window` は
true なので、既存のガードでは捕まらない。

`probeObserver()` を足した。1pxのダミーを1つ観測し、**返ってきてから隠す。**
400ms 返らなければ動きを捨てて中身を出す。Hero は `rAF`×2 と
`setTimeout(300)` を併走させ、先に来たほうで着地させる。
（`lp-visual-knowledge` §6 が手順として書いていたことで、
**このLPは書いてあるとおりに作られていなかった。**）

検証（SP 390×844、`[data-reveal]` は5要素）:

| | `motion-ready` | 隠れたまま残った要素 |
| --- | --- | ---: |
| 通常 | 付く | 0（画面外の分は正しく隠れる） |
| **IOが返らない環境を再現** | **付かない** | **0**（修正前は5） |
| `prefers-reduced-motion: reduce` | 付かない | 0 |

**4. ノンブルが壊れたと誤診した。** 検証スクリプトが `scroll-behavior: smooth`
と競合して、読む時点でスクロールが着地していなかった。**実装は正しかった。**
`scrollBehavior = "auto"` にして再測したら全一致。
**寸法を測るときは慣性・アニメーションを先に殺す。**
