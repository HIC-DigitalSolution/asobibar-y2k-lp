## 依頼内容（2026-11-17）

> 開催店舗は店舗の写真を使ってもっとわかりやすく選べるようにしてほしい
> スキルズやドックスを見て使えそうなものないか確認してください

あわせて「MIX交流上等のバナーをSPサイズで差し替え」。
**イベント名の食い違い（交流上等 / マッチ上等）は「気にするな」と指示あり。触らない。**

## Goal

**9店それぞれの店内が見えて、見比べて選べる。**写真は実物で、推測で当てない。
写真を足してもページが重くならない。

## Scope

- [x] 公式サイト（asobibar.net/shops）から9店の店内写真を取得
- [x] 16:9・800×450 の webp に変換し `assets/shop-<slug>.webp` へ
- [x] `.gitignore` の許可リストに9件追加
- [x] `.venue-link` を写真つきに組み替え（PC 5列 / SP 1列）
- [x] MIXバナーをSPだけ差し替え（`<picture>`）
- [x] **使われていない preload（735KB）を実際に使う画像へ向け直す**

## Non-scope

- **最寄駅・住所は足さない**（依頼者の選択）。データも手元に無い。
- **イベント名の不一致は直さない**（依頼者の指示）。
- `.storepick` ダイアログはそのまま。CTAから開く導線は従来どおり。

## Constraints

- **店舗写真は実物でなければならない。**`no-invented-store-facts`。
  公式の `alt` が店名と一致していたので対応付けは確実。
- **店が増減したら3か所直す**（`.venue-list` / `.storepick` / `assets`）。
- 画像は1枚400KBまで（`image-budget`）。
- **転載の可否は依頼者の判断。**公式サイトから取ることは依頼者が選択した。

## Result

**実装済み（2026-11-17）。** `styles.css?v=493` / `script.js?v=77`。

### ドキュメントを見て、§12 は**採らなかった**

`lp-visual-knowledge` §12（OPUS採用LP）に「一覧は写真1枠＋行の束で見せる」とあり、
持ち込み項目に **「貸切予約の店舗一覧がそのまま当てはまる」** と名指しで書かれている。
**読んだうえで採らなかった。**

§12 は5部署の雰囲気を見せる一覧で、**どの写真が出ても成立する**。
ここは**自分が行く1店を選ぶ**場面で、その店の写真が見えないと選べない。
1枠を回す形だとSPで目当ての店が出るまで待つことになる。**9枚とも出す。**

§12 から取ったのは「カードにしない（枠と影で縦に伸びる）」のほうで、
写真＋店名＋印の3つだけに留めてある。

### 踏んだこと

**最初 4:3 で切ったら、元が 578×325 の店を 2.2倍に引き伸ばしていた。**
16:9 にして 800×450 にすると引き伸ばしは最大1.4倍に収まる。合計 512KB。

**SPで2列のままだと写真が 150×84 まで縮んで店の判別がつかなかった。**
SPは1列にして、写真を左・名前を右に並べた。

### preload が735KBのムダを出していた（この依頼で見つけた別件）

`<link rel="preload" as="image" href="hero-collage-typography-no-disc.jpg">` が
**ページのどこにも出ていない画像**を `fetchpriority="high"` で指していた。
実際のFVは `hero-collage-current.jpg`。**735KBを最優先で落として一度も使わず、
本物のFV画像の取得を押しのけていた。**全文検索で、あのファイルの参照はこの1行だけ。

**写真9枚を足したぶんを、これで取り返した。**

```
                  公開中    写真追加後   preload修正後
スクロール前       4.17MB    4.52MB      3.80MB
最後まで          5.51MB    6.38MB      5.67MB
LCP（4G・CPU4倍）  2992ms      -         2608ms
```

**9枚（512KB）とSPバナー（163KB）を足して、初期表示は公開中より 370KB 軽い。**

### 検証

- 写真と店名の対応 … 公式の `alt` と照合、9件一致
- リンク先 … `.storepick` の9件と完全一致（機械照合）
- `image-budget` … 10ファイルすべて基準内
- 横スクロール／JSエラー … 増加なし・0件
- `harness-check` 機械判定すべて pass

### 公式HPの中も調べた（依頼者の指示・同日）

**9店すべての自前サイトを見た。**結論は「`/img/shops/` の画像が店舗固有のもので、
いま使っているのが正解」。

- **各店サイトの大きい画像は全店共通のブランド素材。**`home-img2-new.jpg` は
  三宮と恵比寿で **MD5 が完全一致**（`bbe8c382...`、287,112バイト）。店の判別に使えない
- 店名を冠した画像があるのは三宮・新宿・恵比寿だけ。新宿と恵比寿のものは
  キャンペーンバナー（`shinjukuage_a_pc` / `ebisu_u29_pc`）で店内写真ではない
- **三宮だけ同じ構図の高解像度版があった**（`sannomiya-shop-poster-a.jpg` 1280×720）。
  元の 578×325 から差し替えた

**心斎橋店と名古屋栄錦通り店は 578×325 のまま。**自前サイトにも高解像度版が無い。
9枚の中でこの2枚だけ一段粗い。**支給素材が来たら差し替える。**

### LINE予約の窓口を公式に合わせた（**解決済み**）

`lin.ee/xxxx` は同じLINEアカウントに対して複数発行できるので、**文字列が違っても
着地先は同じ**。12本すべてを実際に辿って `@ID` で突き合わせ直したところ、
